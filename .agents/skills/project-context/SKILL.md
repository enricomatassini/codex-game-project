# Ripresa e mantenimento del contesto

1. Leggi AGENTS.md e docs/PROJECT.md, docs/STATE.md, docs/BACKLOG.md. Controlla lo stato Git e preserva modifiche esistenti.
2. Leggi solo decisioni, verifiche e codice pertinenti al task. Verifica i fatti sul repository: i documenti possono essere obsoleti.
3. Identifica obiettivo attivo, criteri di accettazione, dipendenze e prossimo passo. Applica le nuove istruzioni dell'utente senza perdere requisiti precedenti compatibili.
4. Se serve delegare, segui docs/AGENT_WORKFLOW.md e assegna ambiti di scrittura distinti. Il coordinatore è l'unico autore dei documenti condivisi di stato.
5. A ogni traguardo aggiorna STATE con fatti verificati, esiti, blocchi e prossimo comando o azione. Aggiorna BACKLOG; registra decisioni stabili in DECISIONS e verifiche in VALIDATION.
6. Prima di chiudere o trasferire il lavoro, lascia un riepilogo breve: cosa è fatto, dove, come è stato verificato, cosa resta e quale decisione manca. Non copiare trascrizioni o segreti. Condensa ripetizioni, conservando le motivazioni utili.

Non dichiarare che il contesto sia sincronizzato con GitHub o conservato in una nuova macchina senza averlo verificato. I file locali e le impostazioni salvate sono stati distinti; indicare chiaramente eventuali modifiche ancora locali.
